Http Interceptors

Uma forma poderosa de gerir todos os seus pedidos e respostas HTTP a partir de um único local.

O que vai ser capaz de fazer?

No final desta aula, você será capaz de:

  • 🎯 Entender o que é um Http Interceptor e qual o seu propósito.
  • 🎯 Criar um intercetor para adicionar cabeçalhos de autenticação a todos os pedidos.
  • 🎯 Lidar com erros HTTP de forma centralizada.
  • 🎯 Registar (log) todos os pedidos e respostas da sua aplicação.

Teoria (com analogia)

O Porteiro dos seus Pedidos

Um Http Interceptor em Angular é uma funcionalidade que se posiciona no meio do caminho entre a sua aplicação e o servidor. Ele pode "intercetar" todos os pedidos HTTP que saem da sua aplicação e todas as respostas que chegam, permitindo-lhe modificá-los ou executar lógica sobre eles de forma global.

💡

Analogia

Pense num intercetor como o porteiro de um hotel. Sempre que um hóspede (a sua aplicação) quer enviar uma carta (um pedido HTTP), o porteiro pode verificar a carta, adicionar um selo do hotel (um token de autenticação) e só depois enviá-la. Da mesma forma, quando chega correio para o hóspede (uma resposta HTTP), o porteiro pode verificar se a carta está danificada (um erro HTTP) antes de a entregar.

Prática (Passo a Passo)

Vamos criar um intercetor para adicionar um token de autenticação a todos os pedidos.

Passo 1: Crie o Intercetor

Use o Angular CLI para gerar um novo intercetor.

ng generate interceptor auth

Passo 2: Implemente a Lógica

No `auth.interceptor.ts`, implemente o método `intercept`.

import { Injectable } from '@angular/core';
import { HttpInterceptor, HttpRequest, HttpHandler } from '@angular/common/http';

@Injectable()
export class AuthInterceptor implements HttpInterceptor {
  intercept(req: HttpRequest<any>, next: HttpHandler) {
    const authToken = 'o-meu-token-secreto';
    const authReq = req.clone({
      headers: req.headers.set('Authorization', `Bearer ${authToken}`)
    });
    return next.handle(authReq);
  }
}

Passo 3: Registe o Intercetor no Módulo

No seu `app.module.ts`, adicione o intercetor ao array de `providers`.

import { HTTP_INTERCEPTORS } from '@angular/common/http';
import { AuthInterceptor } from './auth.interceptor';

@NgModule({
  // ...
  providers: [
    { provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true }
  ],
  // ...
})
export class AppModule { }

Agora, todos os pedidos HTTP feitos com o `HttpClient` incluirão automaticamente o cabeçalho de autorização.

Teste o seu conhecimento

1. Por que a opção `multi: true` é importante ao registar um intercetor?

Explicação: `multi: true` diz ao sistema de injeção de dependências do Angular para adicionar o novo intercetor a um array de intercetores, em vez de substituir qualquer intercetor que já exista. Isto permite criar uma cadeia de intercetores.

Resumo do que aprendeu

Nesta aula, aprendeu sobre Http Interceptors:

  • ✅ O que são e como funcionam no ciclo de vida de um pedido HTTP.
  • ✅ Como criar um intercetor para modificar cabeçalhos de pedidos.
  • ✅ Como registar o seu intercetor para que o Angular o possa usar.

Os intercetores são uma ferramenta essencial para gerir de forma limpa e centralizada as preocupações transversais da sua aplicação, como autenticação e tratamento de erros.
