Módulo 10: Performance Web

2. Resumo da Aula Anterior

No último módulo, aprendeste a configurar o SEO para que o teu site apareça no Google. Hoje, vamos garantir que o teu site é super rápido, porque a velocidade é um dos fatores mais importantes para os utilizadores e para o próprio Google.

3. O Que Vais Aprender Hoje

  • ✅ Estratégias de carregamento de scripts: async e defer.
  • ✅ Otimização de imagens com lazy loading.
  • ✅ O que são o preload e o preconnect.

4. Teoria: A Web Impaciente

Conceito: Performance Web é o conjunto de técnicas para fazer com que um site carregue e responda o mais rápido possível.

🏎️ Analogia: O Pit Stop da Fórmula 1

Imagina um carro de corridas a entrar no pit stop:

  • Scripts normais: São mecânicos que param o carro no meio da pista para trocar pneus (bloqueiam o site).
  • defer: É dizer aos mecânicos para prepararem os pneus e só trocarem quando o carro terminar a volta (o HTML termina de carregar).
  • lazy loading: É só levar combustível para o carro quando ele realmente precisar dele, em vez de carregar o camião todo logo ao início.
  • preload: É avisar a equipa por rádio 5 minutos antes: "Preparem-se, que eu vou precisar disto já a seguir!".

5. Exemplos Práticos

Exemplo 1: Carregamento de Scripts

Evita que o JavaScript bloqueie o desenho do site.

<!-- BLOQUEANTE (Não recomendado para scripts grandes) -->
<script src="pesado.js"></script>

<!-- RECOMENDADO: Executa só no fim da leitura do HTML -->
<script defer src="app.js"></script>

<!-- ÚTIL: Executa o mais rápido possível sem bloquear o HTML -->
<script async src="analytics.js"></script>

Usa sempre defer para os teus ficheiros de lógica principal.

Exemplo 2: Lazy Loading de Imagens

Não carregues o que o utilizador ainda não viu.

<!-- A imagem só carrega quando o utilizador faz scroll até ela -->
<img src="foto-grande.jpg" loading="lazy" alt="Paisagem de Lisboa">

<!-- Imagens no topo do site devem carregar logo (eager) -->
<img src="banner-topo.jpg" loading="eager" alt="Vindo ao site">

O loading="lazy" é uma das formas mais fáceis de acelerar um site com muitas imagens.

Exemplo 3: Antecipar Necessidades

Preload para fontes e estilos críticos.

<!-- Avisa o browser para descarregar a fonte imediatamente -->
<link rel="preload" href="minha-fonte.woff2" as="font" crossorigin>

<!-- Abre a ligação ao servidor do Google Maps antes de ser preciso -->
<link rel="preconnect" href="https://maps.googleapis.com">

Isto remove preciosos milissegundos de espera durante o carregamento.

6. Agora é a Tua Vez!

Vamos otimizar uma página de "Notícias":

  1. Cria uma estrutura com uma imagem de cabeçalho e 5 notícias (com fotos).
  2. Aplica loading="lazy" às fotos das 5 notícias (que estão mais abaixo).
  3. Move os teus <script> para o <head> e usa o atributo defer.
  4. Adiciona um preconnect para um serviço externo (ex: Google Fonts).

8. Resumo do Que Aprendemos

  • 📌 Um site rápido retém mais utilizadores e vende mais.
  • 📌 Usa defer para scripts que não precisam de correr imediatamente.
  • 📌 loading="lazy" é obrigatório para imagens fora da vista inicial.
  • 📌 preload ajuda a carregar recursos críticos (fontes) mais cedo.
  • 📌 preconnect prepara o caminho para servidores externos.

9. Desafios Práticos

Desafio 1: O Teste do Google

Qual é o nome da ferramenta gratuita do Google que dá uma nota de 0 a 100 à performance do teu site?

Solução: O PageSpeed Insights. É a ferramenta padrão para medir a velocidade e receber dicas de melhoria.

Desafio 2: O Peso das Imagens

Além do lazy loading, que outra coisa deves fazer às imagens para que o site não fique lento?

Solução: **Comprimir** as imagens (usar formatos como WebP em vez de PNG pesado) e redimensioná-las para o tamanho que elas realmente vão aparecer no ecrã.

Desafio 3: A Ordem Importa

Se tiveres 10 imagens com loading="lazy" no topo da página, o que acontece?

Solução: Pode ser contraproducente! As imagens que o utilizador vê mal entra no site devem carregar imediatamente (eager). O lazy loading é para o que está "abaixo da dobra" (below the fold).
