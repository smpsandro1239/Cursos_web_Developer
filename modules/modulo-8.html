Módulo 8: Web para Todos

2. Resumo da Aula Anterior

No último módulo, descobriste como a Semântica dá significado ao teu site. Hoje vamos usar esse significado para tornar o teu site inclusivo: acessível a pessoas com deficiência e muito mais fácil de usar para todos.

3. O Que Vais Aprender Hoje

  • ✅ A importância da acessibilidade (a11y).
  • ✅ Como escrever alt text que realmente ajude.
  • ✅ O uso de atributos ARIA para elementos interativos.
  • ✅ Como garantir que o teu site funciona apenas com o teclado.

4. Teoria: Construir Sem Barreiras

Conceito: Acessibilidade significa garantir que o teu site pode ser usado por qualquer pessoa, independentemente da sua capacidade física ou técnica.

🪜 Analogia: O Elevador e a Rampa

Imagina um edifício público:

  • Escadas: É o teu site para alguém que usa o rato perfeitamente.
  • Rampa/Elevador: É a acessibilidade. Ajuda quem usa cadeira de rodas, mas também ajuda uma mãe com um carrinho de bebé ou alguém que carrega malas pesadas.
  • Sinalética em Braille: É o teu atributo alt nas imagens para quem não consegue ver o ecrã.

5. Exemplos Práticos

Exemplo 1: O Texto Alternativo (Alt)

Como descrever imagens para invisuais.

<!-- MAU -->
<img src="foto1.jpg" alt="imagem">

<!-- BOM -->
<img src="receita-bolo.jpg" alt="Bolo de chocolate com cobertura de morango fatiado num prato branco">

<!-- DECORATIVO (Ignorado por leitores de ecrã) -->
<img src="divisor-linha.png" alt="">

Nunca deixes uma imagem importante sem alt. Se for apenas um detalhe visual, usa alt="".

Exemplo 2: Atributos ARIA

Dar nome a botões que são apenas ícones.

<!-- O leitor de ecrã não sabe o que é um ícone de lixo -->
<button aria-label="Eliminar mensagem">
  <i class="fa fa-trash"></i>
</button>

<!-- Indicar que um menu está aberto ou fechado -->
<button aria-expanded="false">Menu</button>

O aria-label diz ao computador o que o botão faz, mesmo que não haja texto visível.

Exemplo 3: Ordem de Foco (Teclado)

Navegar com a tecla TAB.

<!-- Elementos nativos como 'a' e 'button' já são 'focáveis' -->
<a href="#">Link Acessível</a>

<!-- Se precisares que um elemento customizado receba foco -->
<div tabindex="0" role="button">Clique Aqui com o Teclado</div>

Usa o teclado para navegar no teu site. Se não conseguires chegar a um botão usando apenas o TAB, o teu site tem problemas de acessibilidade.

6. Agora é a Tua Vez!

Vamos auditar uma pequena galeria:

  1. Cria 3 imagens de cidades diferentes.
  2. Adiciona a cada uma um alt que descreva o que se vê (ex: "Torre Eiffel iluminada à noite").
  3. Cria um botão com um emoji (ex: 🗑️) e usa aria-label para explicar que serve para "Apagar".
  4. Testa no teu browser: tenta navegar entre os elementos usando apenas a tecla TAB.

8. Resumo do Que Aprendemos

  • 📌 Acessibilidade não é um extra, é um direito.
  • 📌 Usa sempre alt descritivos em imagens de conteúdo.
  • 📌 Usa aria-label em botões que não têm texto.
  • 📌 O teu site deve ser totalmente navegável por teclado.
  • 📌 Mantém um bom contraste entre a cor do texto e o fundo.

9. Desafios Práticos

Desafio 1: A Cor Proibida

Imagina que tens um formulário e dizes: "Os campos a vermelho são obrigatórios". Porque é que isto é um erro de acessibilidade?

Solução: Porque utilizadores daltónicos podem não distinguir o vermelho. Deves usar sempre um símbolo (como *) ou texto (ex: "obrigatório") além da cor.

Desafio 2: Ocultar o que não interessa

Se tiveres um ícone puramente decorativo que não queres que os cegos "ouçam", que atributo podes usar?

<i class="fa fa-star" aria-hidden="true"></i>

O aria-hidden="true" esconde o elemento apenas dos leitores de ecrã.

Desafio 3: Ordem Lógica

Se o teu código HTML tiver o rodapé antes do cabeçalho, mas usares CSS para o colocar no fim, o que acontece a um utilizador cego?

Solução: Ele começará a ouvir o rodapé primeiro! O leitor de ecrã segue a ordem do HTML, não do visual. A ordem do código deve ser sempre lógica.
