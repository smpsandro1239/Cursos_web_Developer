2. Resumo da Aula Anterior

No Módulo 16, aprendemos os atalhos do ES6+ para escrever código mais limpo. Hoje, vamos resolver um problema irritante: por que é que os dados do nosso site desaparecem sempre que fazemos refresh? Bem-vindo ao LocalStorage.

3. O Que Vais Aprender Hoje

  • ✅ O que é o LocalStorage e para que serve.
  • ✅ Como guardar (set) e ler (get) dados.
  • ✅ Converter Objetos para Strings com JSON.stringify.
  • ✅ Converter Strings de volta para Objetos com JSON.parse.

4. Teoria: O Cacifo do Browser

Conceito: O JavaScript vive na memória RAM; quando fechas a aba, tudo morre. O LocalStorage é como um pequeno disco rígido (5MB a 10MB) que o browser reserva para cada site. Os dados ali guardados ficam lá para sempre, mesmo que desligues o computador.

🗝️ Analogia: O Cacifo do Ginásio

Imagina que o teu site é um ginásio:

  • Chave: É o nome que dás à gaveta (ex: "nomeUtilizador").
  • Valor: É o que guardas lá dentro (ex: "Sandro").
  • Persistence: Podes ir para casa, dormir, voltar no dia seguinte e, se usares a chave certa, as tuas coisas continuam lá.

Importante: O cacifo só aceita "roupa dobrada" (Strings). Se quiseres guardar um "equipamento complexo" (Objeto), tens de o desmontar (JSON.stringify) e depois voltar a montar (JSON.parse).

5. Exemplos Práticos

Exemplo 1: Guardar e Ler Texto

Operações básicas de string.

// Guardar
localStorage.setItem("tema", "escuro");

// Ler
const temaSalvo = localStorage.getItem("tema");
console.log(temaSalvo); // "escuro"

// Remover
localStorage.removeItem("tema");

Exemplo 2: O Desafio dos Objetos

Usar JSON para guardar dados complexos.

const user = { nome: "Sandro", pts: 150 };

// ❌ Se fizeres isto, ele guarda "[object Object]"
// localStorage.setItem("usuario", user);

// ✅ O jeito certo:
localStorage.setItem("usuario", JSON.stringify(user));

// Para ler de volta:
const dadosTexto = localStorage.getItem("usuario");
const userObjeto = JSON.parse(dadosTexto);

console.log(userObjeto.nome); // "Sandro"

Exemplo 3: Verificar se existe

Evitar erros ao ler dados vazios.

const nome = localStorage.getItem("nome");

if (nome) {
  console.log(`Bem-vindo de volta, ${nome}!`);
} else {
  console.log("É a tua primeira vez aqui?");
}

6. Agora é a Tua Vez!

Vamos criar um "Lembrador de Nome":

  1. Cria um <input> e um botão "Salvar Nome".
  2. Ao clicar no botão, guarda o valor do input no LocalStorage.
  3. Faz com que, ao carregar a página (window.onload), o site verifique se existe um nome salvo.
  4. Se existir, mostra um alert ou muda um <h1> para dizer "Olá, [Nome]!".

8. Resumo do Que Aprendemos

  • 📌 O **LocalStorage** persiste dados mesmo após fechar o browser.
  • 📌 Usamos **setItem** para guardar e **getItem** para ler.
  • 📌 O armazenamento é por **Chave e Valor**.
  • 📌 **JSON.stringify** e **JSON.parse** são obrigatórios para trabalhar com Objetos/Arrays.

9. Desafios Práticos

Desafio 1: O Limpa-Tudo

Existe um comando que apaga absolutamente TODOS os dados que o teu site guardou no LocalStorage de uma só vez. Qual é?

Solução: localStorage.clear();. Cuidado ao usar, pois remove tudo o que foi guardado pelo domínio!

Desafio 2: Carrinho de Compras

Imagina que o utilizador adiciona produtos a um Array. Como salvarias esse Array no LocalStorage para que ele não o perdesse ao atualizar o site?

Solução: const lista = ["Maçã", "Pêra"]; localStorage.setItem("carrinho", JSON.stringify(lista));

Desafio 3: LocalStorage vs SessionStorage

Existe um "irmão" do LocalStorage chamado SessionStorage. Pesquisa qual a única diferença entre os dois.

Solução: A duração. O SessionStorage apaga os dados automaticamente assim que a aba ou o browser é fechado. O LocalStorage não.
