Módulo 14: Assincronia I (Promessas)

2. Resumo da Aula Anterior

No Módulo 13, aprendemos a usar timers para agendar código. Mas e se tivermos de esperar por algo que não sabemos quanto tempo demora, como carregar dados da internet? Hoje, entramos no mundo das Promises.

3. O Que Vais Aprender Hoje

  • ✅ O conceito de Assincronia (várias coisas ao mesmo tempo).
  • ✅ O que é uma Promise.
  • ✅ Estados da Promise: Pending, Resolved e Rejected.
  • ✅ Tratar resultados com .then() e erros com .catch().

4. Teoria: Não Travar o Browser

Conceito: O JavaScript é "Single Thread", o que significa que só faz uma coisa de cada vez. Se pedires um ficheiro gigante da internet, o site parava todo enquanto esperava. A assincronia permite pedir o ficheiro e continuar a mexer no site. Quando o ficheiro chegar, a Promise "avisa-nos".

🍔 Analogia: O Restaurante de Fast Food

Imagina que pedes um hambúrguer:

  • A Promise (O Pager/Senha): O funcionário não te dá o hambúrguer logo. Dá-te um aparelho que vibra quando estiver pronto. Esse aparelho é a tua **Promise**.
  • O Estado Pending: Estás sentado à espera. A comida ainda não está pronta nem queimou.
  • O Estado Resolved (.then): O aparelho vibra! Vais buscar a comida. Tudo correu bem.
  • O Estado Rejected (.catch): O funcionário diz que o ingrediente acabou. O pedido falhou.

5. Exemplos Práticos

Exemplo 1: Criar uma Promise

O compromisso de um resultado futuro.

const minhaPromessa = new Promise((resolve, reject) => {
  let sucesso = true;

  if (sucesso) {
    resolve("Pedido Concluído! ✅");
  } else {
    reject("Erro no servidor... ❌");
  }
});

Exemplo 2: Usar a Promise

O encadeamento de resultados.

minhaPromessa
  .then((dados) => {
    console.log(dados); // Imprime "Pedido Concluído!"
  })
  .catch((erro) => {
    console.log(erro);
  });

Exemplo 3: Promise com Tempo

Simular o carregamento de um utilizador.

function carregarUser() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({ id: 1, nome: "Sandro" });
    }, 2000);
  });
}

carregarUser().then(user => console.log(user.nome));

Aqui simulamos um atraso de 2 segundos de rede usando a Promise + setTimeout.

8. Resumo do Que Aprendemos

  • 📌 **Assincronia** permite que o site não congele enquanto espera.
  • 📌 Uma **Promise** é um objeto que diz: "Já te respondo!".
  • 📌 **.then()** é para o cenário de sucesso.
  • 📌 **.catch()** é vital para evitar erros fatais na consola.

9. Desafios Práticos

Desafio 1: Carregamento Infinito?

O que acontece se criares uma Promise mas nunca chamares nem o resolve nem o reject? Qual o estado em que ela fica?

Solução: Ela fica para sempre no estado **Pending** (Pendente). O código do .then ou .catch nunca será executado.

Desafio 2: Múltiplos Then

Podes colocar vários .then() em baixo uns dos outros (encadeados)? Qual a vantagem disso?

Solução: Sim! Chama-se **Promise Chaining**. Permite tratar os dados por passos (ex: extrair o nome -> transformar em maiúsculas -> mostrar no ecrã).

Desafio 3: O Finalmente

Existe um terceiro método chamado .finally(). Pesquisa para que serve e quando o devemos usar.

Solução: O .finally() corre **sempre**, quer a Promise tenha dado certo ou errado. É ideal para esconder um ícone de "Loading", por exemplo.
