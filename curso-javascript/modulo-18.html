2. Resumo da Aula Anterior

No Módulo 17, aprendemos a salvar dados permanentemente com o LocalStorage. Hoje, vamos aprender a lidar com o pior inimigo (ou melhor amigo) do programador: o ERRO. Vamos aprender a caçar bugs.

4. Teoria: Ser o Detetive do Teu Código

Conceito: Erros não são o fim do mundo; são sinais de trânsito. O JavaScript tem formas de nos avisar quando algo corre mal, e nós temos ferramentas para "pausar" o tempo e observar o que está a acontecer.

🕵️ Analogia: O Detetive e a Cena do Crime

Imagina que o teu código é um percurso de dominó:

  • O Erro: É quando uma peça cai para o lado errado e o movimento para.
  • Console.log: É tirares fotos em várias partes do percurso para ver onde as peças ainda estavam em pé.
  • Debugger: É congelares o tempo exatamente no momento em que a peça caiu para observares com uma lupa quem é que lhe deu o toque.
  • Try...Catch: É meteres uma rede de segurança. Se a peça cair, a rede apanha-a e não deixa que o resto do cenário se estrague.

5. Exemplos Práticos

Exemplo 1: Try...Catch na Realidade

Evitar que o site trave por um erro inesperado.

try {
  // Código que pode falhar
  const user = JSON.parse("texto-invalido-json");
  console.log(user);
} catch (erro) {
  // O que fazer se falhar
  console.warn("Ups! Os dados estavam corrompidos.");
  console.error("Detalhes técnicos: ", erro.message);
}

Exemplo 2: O Comando Debugger

Pausar o browser automaticamente.

function calcularTotal(preco, taxa) {
  const total = preco + taxa;

  // Abre o inspetor e o código vai parar aqui!
  debugger;

  return total;
}

calcularTotal(10, 2);

Quando o browser encontra o `debugger`, ele para tudo e deixa-te ver o valor de `total` antes de a função acabar.

Exemplo 3: Lançar o teu próprio erro

Forçar uma paragem se algo não for aceite.

function setIdade(idade) {
  if (idade < 0) {
    throw new Error("A idade não pode ser negativa!");
  }
  return idade;
}

try {
  setIdade(-5);
} catch (e) {
  alert(e.message);
}

6. Agora é a Tua Vez!

Vamos caçar um culpado:

  1. Escreve um código que tenta ler uma variável que não existe (ex: console.log(xpto)).
  2. Observa o erro vermelho na consola (F12). Que tipo de erro é? (ReferenceError?).
  3. Envolve esse código num try...catch para que a mensagem apareça num alert amigável em vez de um erro vermelho.
  4. Cria uma função com o comando debugger lá dentro e corre-a. Explora os botões "Step Over" e "Play" no Inspetor do browser.

9. Desafios Práticos

Desafio 1: O Erro Silencioso

Porque é que nunca deves deixar um bloco catch (e) { } vazio e sem código nenhum lá dentro?

Solução: Chama-se "engolir o erro". Se algo falhar, tu nunca vais saber porquê, o que torna o debugging quase impossível no futuro.

Desafio 2: Reference vs Type Error

Se tentares apagar uma propriedade de um valor que é `null`, que tipo de erro recebes? (Reference ou Type?).

Solução: Recebes um TypeError. O JavaScript sabe o que é o valor, mas diz que não podes fazer aquela operação naquele "tipo" de dado.

Desafio 3: O Ponto de Interrupção

Sabias que podes colocar o efeito do debugger sem escrever código? Pesquisa como colocar "Breakpoints" diretamente no separador "Sources" do Inspetor do Chrome.

Solução: Basta clicar no número da linha no separador Sources. Fica uma marca azul e o browser para ali sempre que passar por aquela linha.
