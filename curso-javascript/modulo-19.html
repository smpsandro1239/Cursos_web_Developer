4. Teoria: Código é para Humanos

Conceito: Computadores conseguem ler qualquer "maralhal" de código que funcione. No entanto, o código é escrito para ser mantido por pessoas. Código profissional é **limpo**, **simples** e **organizado**.

📚 Analogia: A Biblioteca vs O Quarto Bagunçado

Imagina que estás à procura de uma informação:

  • Código Mau (Quarto Bagunçado): As meias estão em cima dos livros, os papéis não têm nome e estão todos no chão. Podes até encontrar o que queres, mas demoras horas e ficas irritado.
  • Código Limpo (Biblioteca): Cada livro tem um título claro no lombo, está na prateleira certa e as secções estão bem sinalizadas. Encontras o que precisas em segundos.

5. Exemplos Práticos

Exemplo 1: Nomes Significativos

Dar nome ao que a variável REALMENTE faz.

// Código Mau ❌
const d = 30; // 30 o quê? Dias? Dinheiro?
function calc(a, b) { return a * b; }

// Código Limpo ✅
const diasParaExpulso = 30;
function calcularAreaRetangulo(largura, altura) {
  return largura * altura;
}

Exemplo 2: O Princípio DRY

Não te repitas. Cria funções para tarefas comuns.

// Código Mau (Repetitivo) ❌
const preco1 = 100 + (100 * 0.23);
const preco2 = 50 + (50 * 0.23);

// Código Limpo ✅
const aplicarIVA = (preco) => preco + (preco * 0.23);

const total1 = aplicarIVA(100);
const total2 = aplicarIVA(50);

Exemplo 3: Funções Pequenas

Uma função deve fazer apenas UMA coisa bem feita.

// Em vez de uma função gigante que valida, guarda e envia email...
// Divide em:
function validarEmail(email) { ... }
function salvarNoBanco(dados) { ... }
function enviarConfirmacao() { ... }

6. Agora é a Tua Vez!

Vamos refatorar (limpar) um código:

  1. Olha para este código: let x = 1.23; function f(v) { return v * x; }.
  2. Muda o nome de x para TAXA_CONVERSAO_EURO.
  3. Muda o nome da função para converterDolarParaEuro.
  4. Usa o CamelCase (ex: minhaVariavel) em vez de tudo junto ou com hífens.
  5. Cria uma única função que use as ferramentas de módulos anteriores (Ex: Arrow Functions) para tornar o código mais moderno e limpo.

8. Resumo do Que Aprendemos

  • 📌 Escreve código para que o teu "Eu do futuro" o entenda.

9. Desafios Práticos

Desafio 1: O Detetive de Código

Pega num ficheiro de JavaScript que tenhas escrito anteriormente e tenta renomear 3 variáveis para nomes mais claros. Notas diferença na facilidade de leitura?

Dica: Se tens uma variável data, tenta ser mais específico: dataNascimento ou dataCriacaoPost.

Desafio 2: Comentários vs Código Limpo

Muitos dizem: "Se precisas de um comentário para explicar o que o código faz, o código não está limpo". O que achas disto? Quando é que um comentário é realmente útil?

Solução: Comentários devem explicar o PORQUÊ (a intenção) e não o O QUÊ (que o próprio código já deve dizer).

Desafio 3: KISS

Pesquisa o que significa o acrónimo KISS no mundo do software e como ele se aplica ao JavaScript.

Solução: Keep It Simple, Stupid! (Mantém isto simples, estúpido!). Lembra-nos que a solução mais simples é quase sempre a melhor.
